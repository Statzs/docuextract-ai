# Deploying the public demo (free tier)

This guide puts DocuExtract AI online so anyone can click **Try it now** with no
sign-up, no install and no API key. It uses three free services:

| Piece | Service | What it runs |
|---|---|---|
| Database | **Supabase** | PostgreSQL |
| API | **Render** | the FastAPI Docker image (`backend/`) |
| Web app | **Vercel** | the static React build (`frontend/`), plus a proxy for `/api/*` |

Expect about 30 minutes. You can sign in to all three with your GitHub account. Free plans
should not charge you; if any of them asks for a payment method, that is your call.

```
Visitor ──▶ Vercel (static app)
              │  /api/*  + secret header x-origin-secret
              ▼
           Render (FastAPI) ──▶ Supabase (PostgreSQL)
```

---

## 0. Publish the repository

1. On GitHub, create an **empty public** repository named `docuextract-ai` under `Statzs`
   (no README, license or .gitignore: the project has its own).
2. In the project folder:
   ```powershell
   git remote add origin https://github.com/Statzs/docuextract-ai.git
   git push -u origin main
   ```
3. In the repository, open **Actions** and check that the *CI* workflow goes green. This is
   the first time it runs anywhere, so if a job fails, send me the log.
4. **Settings → Code security → Private vulnerability reporting → Enable** (SECURITY.md
   points people there).

## 1. Supabase (database)

1. https://supabase.com → **New project**. Pick a region close to where you'll create the
   Render service (for example, both in the US East or both in Frankfurt).
2. Set a strong **database password** and save it in your password manager.
3. When the project is ready: **Connect** (top bar) → **Connection string** → choose
   **Session pooler**. Copy the URI. It looks like
   `postgresql://postgres.abcd1234:[YOUR-PASSWORD]@aws-0-eu-central-1.pooler.supabase.com:5432/postgres`.
4. Replace `[YOUR-PASSWORD]` with your password. If the password contains characters such
   as `@ : / ? #`, URL-encode them (`@` → `%40`), or pick a password without them.

Keep this `DATABASE_URL` private. Tables are created automatically when the API starts, and
Row Level Security is switched on so Supabase's public Data API cannot read them.

> Supabase pauses free projects after a week without activity. If the demo stops working
> after a quiet week, open the Supabase dashboard and click **Restore**.

## 2. Render (API)

1. https://render.com → **New → Blueprint** → connect GitHub and choose `docuextract-ai`.
   Render reads [`render.yaml`](../render.yaml) and proposes a free web service named
   `docuextract-api`.
2. Fill in the values it asks for:

   | Variable | Value now |
   |---|---|
   | `DATABASE_URL` | the Supabase URI from step 1 |
   | `APP_URL` | `https://example.com` for now (fixed in step 4) |
   | `CORS_ORIGINS` | `["https://example.com"]` for now (fixed in step 4) |
   | `GEMINI_API_KEY` | leave empty for now (step 6); without it documents are read with PDF text and OCR |
   | `SMTP_*` | leave empty (password reset is then hidden in production) |

   `JWT_SECRET` and `ORIGIN_SECRET` are generated by Render; you don't type them.
3. **Apply**. The first build takes a few minutes. When it is live, note the hostname,
   for example `docuextract-api-x1y2.onrender.com`.
4. Quick check in a browser:
   - `https://<render-host>/api/health` → `{"status":"ok"}`
   - `https://<render-host>/api/config` → `{"detail":"Forbidden"}`. **This is correct**: the
     API only answers requests that come through Vercel (the origin lock).
5. Open the service's **Environment** tab and copy the value of `ORIGIN_SECRET`. You need it
   in step 3. Treat it like a password.

## 3. Vercel (web app)

1. In `frontend/vercel.json`, replace `YOUR-BACKEND-HOST` with the Render hostname (no
   `https://`, no trailing slash). Commit and push:
   ```powershell
   git commit -am "Point the Vercel proxy at the Render API"
   git push
   ```
   (Or ask me to make this edit once you have the hostname.)
2. https://vercel.com → **Add New → Project** → import `docuextract-ai`.
3. Set **Root Directory** to `frontend`. Vercel detects Vite; keep the defaults.
4. Under **Environment Variables** add `ORIGIN_SECRET` with the value copied from Render.
5. **Deploy**. Note the URL, for example `https://docuextract-ai.vercel.app`.

If you add or change `ORIGIN_SECRET` after the first deploy, redeploy (Deployments → ⋯ →
Redeploy) so it takes effect.

## 4. Connect the two

Back in Render → `docuextract-api` → **Environment**:

| Variable | Value |
|---|---|
| `APP_URL` | your Vercel URL, e.g. `https://docuextract-ai.vercel.app` |
| `CORS_ORIGINS` | `["https://docuextract-ai.vercel.app"]` (JSON list, with quotes) |

Save, then **Manual Deploy → Deploy latest commit** if Render does not redeploy by itself (a Blueprint created from a public URL does not auto-deploy on push).

## 5. Verify like a recruiter would

1. Open the Vercel URL in a **private window**. The first visit may show *"Waking up the
   server"* for up to a minute (Render's free plan sleeps after 15 minutes idle).
2. Click **Try it now — no signup**. Follow the tour: open a document, extract a
   sample, validate, export a CSV.
3. In Render → **Logs**, find `demo workspace requested from <IP>`. It should show **your
   own public IP** (compare with a "what is my IP" site). Try once more from your phone on
   mobile data: the IP should differ. If every request shows the same IP, or an IP that
   isn't yours, tell me. It means the per-IP rate limits would treat all visitors as one,
   and the client-IP header needs changing. (Verified on the reference deployment:
   with `CLIENT_IP_HEADER=x-forwarded-for` the log shows the real IP even when the request
   carries forged `X-Forwarded-For`/`X-Real-IP` headers.)
4. Optional: sign up with a real email and sign in again.

When it all works, share `https://<your-vercel-url>/demo`: that link creates a fresh demo
workspace and opens it in one step, so it is the best link for a CV or LinkedIn. I can add
it to the README.

## 6. Turn on AI, Google/GitHub sign-in and the admin panel (optional)

Each of these needs a value only you can create, because it is tied to your own Google or
GitHub account. Add every value in **Render → `docuextract-api` → Environment** (never in
the code or in Vercel), click **Save, rebuild and deploy**, and wait until the service is
live again. Below, `APP` means your Vercel URL, for example
`https://docuextract-ai-three.vercel.app`.

### Gemini key (AI reading)

1. Go to https://aistudio.google.com/apikey and sign in with your Google account.
2. **Create API key**. If it asks for a project, create a new one. **Do not set up billing
   on that project**: without billing, the key can only use the free tier and can never
   cost money. When the free quota is used up, Google refuses the call and DocuExtract
   reads the document without AI.
3. Render → `GEMINI_API_KEY` = the key. Keep `GEMINI_MODEL` = `gemini-3.5-flash-lite`
   (free tier, reads PDFs and images).
4. Keep the daily caps low (the blueprint sets `AI_DAILY_LIMIT_PER_USER=10` and
   `AI_DAILY_LIMIT_GLOBAL=100`); you can change them later in the admin panel. Keep the
   global cap under the free daily quota shown for your key in AI Studio.

Free-tier privacy: Google may use content sent on the free tier to improve its products.
The app tells users this next to the AI option and offers **Private (no AI)**.

### Google sign-in

1. Go to https://console.cloud.google.com and choose (or create) a project. It can be the
   same project as the Gemini key; billing is not needed.
2. Open **Google Auth Platform** (search "OAuth consent" in the top bar).
   - **Branding**: app name `DocuExtract AI`, your support email, and under *Authorized
     domains* add `vercel.app`. Save.
   - **Audience**: user type **External**. Then **Publish app** so anyone can sign in
     (the app only asks for name and email, which needs no Google review).
3. **Clients → Create client** → type **Web application**, name `DocuExtract`.
   - *Authorized JavaScript origins*: `APP`
   - *Authorized redirect URIs*: `APP/api/auth/oauth/google/callback`
   - **Create**, then copy the **Client ID** and the **Client secret**.
4. Render → `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET`.

### GitHub sign-in

1. Go to https://github.com/settings/developers → **OAuth Apps → New OAuth App**.
2. *Application name* `DocuExtract AI`, *Homepage URL* `APP`, *Authorization callback URL*
   `APP/api/auth/oauth/github/callback`. Leave *Enable Device Flow* off. **Register**.
3. Copy the **Client ID**, then **Generate a new client secret** and copy it (it is shown once).
4. Render → `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`.

The sign-in buttons appear automatically once both values of a provider are set.

### Admin panel

1. Render → `ADMIN_EMAILS` = the email of your Google or GitHub account (several: separate
   them with commas).
2. After the redeploy, sign in **with Google or GitHub** (the email must be verified by the
   provider; an email/password account is not enough). *Admin panel* appears in the menu.
3. Click **Check the key now** to confirm the Gemini key works.

### Check it worked

- The sign-in page shows *Continue with Google* / *Continue with GitHub*, and both sign you in.
- Upload a document in your account with **Smart (AI)**: the badge says *Read by AI*.
- In a private window, a normal account opening `APP/app/admin` gets "not found".

## Optional: password reset emails


Set `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` and `SMTP_FROM` from any SMTP
provider with a free tier. Until then, the "Forgot password?" link stays hidden in production.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Every API call returns 403 through Vercel | `ORIGIN_SECRET` missing or different in Vercel, or not redeployed after adding it |
| Vercel shows 404 for `/api/...` or a DNS error | `YOUR-BACKEND-HOST` not replaced in `frontend/vercel.json`, or replaced with `https://` included |
| Render deploy fails at startup with `JWT_SECRET` / `CLIENT_IP_HEADER` error | a generated secret was deleted; restore it in the Environment tab |
| Render logs show a database connection error | wrong password in `DATABASE_URL`, unencoded special characters, or the Supabase project is paused |
| Google/GitHub says *redirect_uri_mismatch* | the callback URL in the provider differs from `APP_URL/api/auth/oauth/<provider>/callback` (check https and no trailing slash) |
| Signing in works but you are immediately signed out | `APP_URL`/`CORS_ORIGINS` don't match the Vercel URL, or you are using the Render URL directly instead of the Vercel one |

## What this setup costs to run

Nothing on the free plans, with these trade-offs: the API sleeps when idle (first request
up to ~1 minute), Supabase pauses after a week of inactivity, and each free tier has usage
limits far above what a portfolio demo needs.
